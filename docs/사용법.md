# 사용법 — 팀원용 매뉴얼

> 이 vault(`docs/`)를 어떻게 쓰는지에 대한 안내. **5분 안에 다 읽힘.**

## 0. 한 줄 요약

**결정·맥락·진행 상황을 코드 옆에 같이 두는 팀 두뇌.** 우리가 직접 쓰고, Claude가 같이 읽고/씁니다.

## 1. 설치 (1회만)

1. [Obsidian](https://obsidian.md/) 설치
2. Obsidian 첫 화면 → **"다른 볼트 열기"** → **`weeth-client/docs/`** 폴더 선택
3. 좌측 사이드바에서 폴더 구조 확인되면 끝

> ⚠️ **새 볼트 만들지 마세요.** 기존 `docs/` 폴더를 _여는_ 거예요. 그래야 git으로 팀과 공유됩니다.

### 추천 플러그인 (선택)

- **Templates** (코어, 켜기만 하면 됨) — 양식 빠르게 삽입
- **Daily Notes** (코어) — 오늘 날짜 회의록/로그 단축키 생성
- **Git** (커뮤니티) — 자동 커밋/풀

## 2. 매일 하는 일

### 아침 (5분)

1. `git pull`
2. 옵시디언 열기
3. `로그/` 폴더에서 **어제 팀원들 세션로그 훑기** — 1분이면 어제 무슨 일 있었는지 파악됨
4. 오늘 작업 시작 시 본인 세션로그 파일 생성: `로그/세션로그-{본인이름}-{YYYY-MM-DD}.md`

### 작업 중

- Claude Code/Desktop과 한 **결정/막힌 점** 그때그때 세션로그에 한 줄씩
- 도메인 용어 헷갈리면 → [[아키텍처/도메인-용어집]]
- "왜 이렇게 하기로 했었지?" → [[아키텍처/결정-기록/README|ADR]]
- 한참 막혔다가 풀린 에러 → [[트러블슈팅/README]]에 추가

### 퇴근 전 (3분)

- 세션로그 "공유할 것" 섹션 채우기
- 변경사항 커밋 (코드 + docs/ 같이)

## 3. 회의 있는 날

1. 회의 _시작 전_: `회의록/{날짜}.md` 생성 (`템플릿/회의록-템플릿` 복사) → 안건만 미리 적기
2. 회의 _중_: 결정/액션 아이템만 빠르게
3. 회의 _후_: 정리 + 링크 보강
4. 큰 결정이 나왔으면 → 별도 [[아키텍처/결정-기록/README|ADR]]로 승격

## 4. 어떤 걸 어디에 적나? (헷갈릴 때)

| 적고 싶은 것                     | 어디                               |
| -------------------------------- | ---------------------------------- |
| 오늘 내가 한 작업                | `로그/세션로그-{이름}-{날짜}.md`   |
| 회의에서 정한 것                 | `회의록/{날짜}.md`                 |
| "왜 이 라이브러리/패턴을 골랐나" | `아키텍처/결정-기록/ADR-XXX.md`    |
| 새 용어 정의                     | `아키텍처/도메인-용어집.md`에 추가 |
| 디버깅 삽질 → 해결               | `트러블슈팅/{도메인}-{제목}.md`    |
| 누가 뭘 맡았나                   | `기획/기능별-담당.md` 업데이트     |
| 학습한 외부 자료                 | `레퍼런스/`                        |

## 5. Claude와 같이 쓰는 법 (핵심)

이게 진짜 활용 포인트입니다.

### 작업 시작할 때

> "오늘 게시판 댓글 기능 작업할 거야. `docs/아키텍처/도메인-용어집.md`의 Comment 부분 먼저 읽고, 어제 내 세션로그 (`docs/로그/세션로그-{이름}-{어제}.md`)도 확인해줘."

→ Claude가 컨텍스트 즉시 잡음. 매번 코드 grep 안 해도 됨.

### 결정한 후

> "방금 정한 거 ADR로 만들어줘. `docs/템플릿/ADR-템플릿.md` 양식으로, 번호는 다음 번호로."

→ ADR이 사람 손 안 거치고 자동 작성됨.

### 막혔다 풀린 후

> "방금 그 에러 `docs/트러블슈팅/`에 새 파일로 정리해줘. 증상/원인/해결 양식으로."

→ 다음 사람이 같은 삽질 안 함.

### 세션 끝낼 때

> "오늘 한 일들 `docs/로그/세션로그-{이름}-{오늘}.md`에 정리해줘. 커밋한 거랑 결정 사항 포함해서."

→ 매일 로그가 자동으로 쌓임.

### 도메인 새 단어가 코드에 생겼을 때

> "방금 만든 `XYZ` 타입을 `docs/아키텍처/도메인-용어집.md`에 추가해줘. 적절한 섹션에."

→ 용어집이 코드와 자동 동기화.

## 6. 옵시디언 기능 활용

### 위키 링크 `[[문서명]]`

- 다른 문서 참조할 때 **무조건** `[[ ]]`로
- 백링크 패널(우측 사이드바)에서 "이 문서를 언급한 모든 곳" 자동 표시
- 예: `도메인-용어집`에서 "Cardinal"을 검색하면 → 그 단어를 쓴 ADR/회의록/로그가 다 나옴

### 그래프 뷰

- 좌측 사이드바 그래프 아이콘
- ADR ↔ 회의록 ↔ 트러블슈팅 연결망 시각화
- 어느 결정이 어디로 퍼져있는지 한눈에

### 빠른 전환 `Ctrl+O`

- 파일명 일부만 쳐도 점프
- 가장 많이 쓰는 단축키

### 검색 `Ctrl+Shift+F`

- 전체 vault에서 텍스트 검색
- "Cardinal 관련 결정 다 어디 있지?" → 1초

## 7. 안 하면 안 되는 것 (Don'ts)

- ❌ **새 볼트 만들지 않기** — `docs/` 폴더를 열어야 함
- ❌ **Claude 대화 전문을 통째로 붙여넣지 않기** — 결정과 이유만 정리
- ❌ **개인 메모/사담을 vault에 넣지 않기** — 팀 공용 두뇌
- ❌ **결정을 코드에만 박지 않기** — `forwardRef` 금지 같은 규칙이 ADR 없으면 6개월 뒤엔 아무도 이유를 모름
- ❌ **`docs/` 따로 커밋하지 않기** — 코드 PR과 같이 묶어서

## 8. 자주 묻는 질문

**Q: 그냥 노션/슬랙으로 하면 안 됨?**
A: 노션도 좋지만 (1) 코드와 같은 git에 있어 PR 리뷰가 됨, (2) Claude가 직접 읽고 쓸 수 있음, (3) 마크다운이라 락인 없음. 노션은 회의록/위키, 옵시디언은 결정/아키텍처처럼 혼용해도 OK.

**Q: 매번 로그/ADR 쓰는 게 부담**
A: 사람이 쓰지 마세요. Claude에게 시키세요 (5번 참고). 사람은 *확인*만.

**Q: 문서가 코드와 안 맞게 됐을 때**
A: 발견자가 고칩니다. CLAUDE.md 규칙처럼 PR에 "docs/도 같이 업데이트했나?" 체크박스 추가하는 걸 추천.

**Q: 옵시디언 안 쓰고 그냥 VSCode에서 마크다운 봐도 됨?**
A: 됩니다. 위키링크와 백링크가 안 보일 뿐, 내용은 같음. 가볍게 쓰고 싶은 사람은 그래도 OK.
