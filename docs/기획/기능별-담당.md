# 기능별 담당

"누가 무엇을 책임지는가"를 한눈에. 코드 충돌이 예상되는 작업은 **시작 전에 담당자와 대화**한다.

- User

| 영역                             | 담당           | 상태 | 관련 문서 |
| -------------------------------- | -------------- | ---- | --------- |
| 인증 (auth) - 로그인, 회원가입   | 계다현         | 완료 |           |
| 게시판 (board)                   | 서나영         | 완료 |           |
| 출석 (attendance)                | 서나영         | 완료 |           |
| 마이페이지 (mypage)              | 이유진, 김지원 | 완료 |           |
| 홈 (home)                        | 김지원         | 완료 |           |
| 랜딩 (Landing)                   | 김지원         | 완료 |           |
| 디자인 시스템 (`components/ui/`) | @공동          | 상시 |           |

- Admin

| ---------------------------- | -------------- | ---- | --------- |
| 멤버 (Member)                | 이유진         | 완료 |           |
| 게시판 (Board)               | 이유진         | 완료 |           |
| 일정/세션 (Schedule/Session) | 이유진         | 완료 |           |
| Navigation                   | 이유진         | 완료 |           |

## 작업 규칙

- 시작 전 `git pull`로 최신 상태 받기
- 작업 끝나면 커밋 + 푸시 (브랜치는 `feat/`, `fix/`, `refactor/` 등)
- **main 직접 커밋 금지**, PR로 들어간다
- 다른 사람 담당 영역을 건드려야 하면 → 회의록이나 슬랙으로 먼저 합의
- 공통 영역(`components/ui/`, `lib/cn.ts`, 디자인 토큰) 수정은 PR 리뷰 필수
