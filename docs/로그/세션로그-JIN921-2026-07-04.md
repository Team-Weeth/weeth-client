### 2. `getPaymentTargets` — 첫 페이지 고정 조회 해제(전체 페이지 합산)

- **파일:** [`adminDues.ts`](../../src/lib/apis/adminDues.ts) (`getPaymentTargets`)
- **문제:** `page: 0` 고정 + 기본 `size = 100`. 소비자([`DuesSetupStep2`](../../src/components/admin/dues/setup/DuesSetupStep2.tsx) / [`PaymentTargetModal`](../../src/components/admin/dues/modal/PaymentTargetModal.tsx) / [`DuesSetupStep5`](../../src/components/admin/dues/setup/DuesSetupStep5.tsx))가 `targets.content`를 **전체 목록**처럼 사용하는데, 100건 초과분이 빠짐
- **수정:** 첫 페이지 조회 후 `totalPages > 1`이면 나머지 페이지를 `Promise.all`로 병렬 조회해 `content`를 병합. 반환 형태는 기존 axios 응답(`ApiResponse<PaymentTargetsData>`) 그대로라 소비자·`duesPaymentTargetsQueryOptions` 코드 변경 없음

### 판단 — page 인자 방식 vs 전체 합산 방식

두 방식 중 **전체 합산**을 선택.

- 현재 세 소비자 모두 페이지네이션 UI 없이 `content`를 전체 목록으로 사용 → page 인자를 노출하면 각 소비자에 페이징 루프를 추가로 넣어야 함
- API 함수 한 곳에서 합쳐 내려주는 편이 소비자 변경 0으로 가장 적은 침습
