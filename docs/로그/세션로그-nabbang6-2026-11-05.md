### 1. `next/image` 전환 — ImageCard / Avatar

- **ImageCard**: 원격 URL에 대해 `<img>` → `next/image` 교체. 로컬 blob URL은 최적화 불가이므로 `<img>` 유지(isLocal 분기).
  - `sizes` 프롭 추가 (기본 `'100vw'`): 썸네일 `72px`, 1개 단독 `calc(100vw-32px)/832px`, 복수 `~250px` 등 사용처별 명시.
  - `priority` 프롭 추가: LCP 대상 이미지에 `fetchpriority="high"` + lazy 비활성화.
- **Avatar**: Radix UI `AvatarPrimitive` 제거 → `next/image` 기반 커스텀 구현.
  - `AvatarContext`로 `status`(`idle`/`loaded`/`error`)를 하위 컴포넌트에 공유.
  - `AvatarFallback`은 `status === 'loaded'` 이면 렌더 중단; `delayMs` 로 폴백 노출 지연 지원.
  - `UserProfileHeader`에서 `width`/`height` 하드코딩 제거 (컨텍스트의 `size` 값 사용).

## 결정 사항

### next/image vs `<img>` 혼용 (ImageCard)

로컬 blob URL은 `next/image`의 최적화 대상이 아니라 `<img>` 유지가 맞음. 업로드 완료 후 URL이 원격으로 교체되므로 최적화 경로에 자연히 합류.

### Avatar에서 Radix UI 제거

Radix `AvatarPrimitive`의 fallback은 이미지 로드 여부를 내부적으로 감지해 토글했는데, `next/image`와 혼용 시 `onLoad`/`onError` 타이밍이 맞지 않아 fallback이 항상 보이거나 항상 숨겨지는 문제 발생. `AvatarContext` + `useState`로 직접 관리하는 쪽이 `next/image`와 명확하게 연동됨.

### CommentSection SSR 비활성화

댓글은 초기 페이지 HTML에 포함될 필요 없음(SEO 무관, 항상 클라이언트 인터랙션 필요). SSR 제외로 PostDetailContent 서버 번들 크기 감소.
